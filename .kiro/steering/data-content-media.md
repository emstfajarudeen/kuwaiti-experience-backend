# Data, content, and media rules

- Schema changes belong in ordered Lucid migrations under `database/migrations`. Respect existing foreign keys and localized translation tables. Migrations are destructive on rollback; back up live MySQL data before production schema operations and never use rollback as a content reset.
- Write operations should use the existing transaction pattern and audit behavior. Preserve reference protections: categories/types and content cannot be deleted or changed when dependent records make that unsafe. Keep admin users and password hashes protected from content-reset behavior.
- Use the current content lifecycle: draft -> published -> archived, with publication requiring the existing completeness rules. Public queries must retain publication and visibility filters. Demo seed data is explicitly placeholder content and must not be presented as verified visitor information.
- There is no shared media library. Each image belongs to exactly one record slot (`places.cover_image_key`, `place_images.storage_key`, `category_types.image_key`, `home_content.hero_image_key`, `site_settings.logo_image_key`, movie posters), uploaded through that record's CMS form or admin endpoint. Files are private local Drive storage under `storage/uploads` (tests use `storage/test-uploads`) and are served through `/api/v1/images/{key}` only while owned by visible content, or through authenticated admin previews, never a static alias. Accepted source images are JPEG/JPG/PNG/WebP; the pipeline decodes with Sharp, enforces size/pixel/file-count bounds, rotates, and stores `<uuid>.webp` output.
- Replacing or removing an image, or deleting its record, deletes the file after the database transaction commits; database and file deletion are separate operations. Use `node ace images:prune-orphans` (inspect, then `--delete`) for managed orphan cleanup; do not broaden cleanup to arbitrary files. Back up uploads together with the database, and do not assume local storage supports multiple application instances.
- Preserve editorial and localization constraints: English required fields remain authoritative for publication, Arabic fields fall back independently where implemented, prices are KWD-shaped decimals formatted to three places, and transport date-times are interpreted in `Asia/Kuwait`. The enquiry endpoint creates a WhatsApp link only; it does not reserve or confirm a booking.
